# User Authentication Implementation Plan

> **For agentic workers:** Execute the tasks inline using superpowers:executing-plans; request an independent security review before completion.

**Goal:** Deliver secure login-only user management with an idempotent superadmin seed and 24-hour sessions.

**Architecture:** SQLAlchemy stores users, opaque session digests, and persistent throttle counters. Business logic is split per operation under use_cases; routes only adapt HTTP. Migration access is confined to the backend database role.

**Tech Stack:** FastAPI, SQLAlchemy, Alembic, psycopg, Argon2id, unittest, HTTPX.

**Spec:** ../specs/2026-10-14-user-auth-design.md

## Global Constraints

- Follow agent/rules.md; one table per model file and one use-case operation per file.
- No public registration or frontend changes.
- Password minimum 8 characters, uppercase, lowercase, special character.
- Session lifetime 24 hours; logout and password changes revoke sessions.
- Only superadmin may change the superadmin account; its identity survives username edits.
- No credential literals in tracked seed code or API error responses.

## Review Focus

- Concurrent password changes versus login cannot leave a newly valid session using the old password.
- Username changes cannot bypass superadmin protection or seed a second privileged account.
- Supabase API roles cannot read password hashes or sessions.
- Browser cookie requests cannot mutate data without trusted Origin and session-bound CSRF.
- Rate limits persist across workers and unknown-user errors do not disclose account existence.
